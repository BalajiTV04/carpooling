# Module notes — one per module, and they feed the SRS / final report

Every module in the project has a note here. They all follow the same 9-part
template, so the report can be assembled from them directly:

1. **Concept / why** — the problem and the design choice that solves it
2. **Prerequisites** — what the module depends on
3. **Rules** — the pure functions that own the policy
4. **Code map** — how the API, models, schema and frontend connect
5. **Integration** — what it reads from and what reads it
6. **Run + test** — the exact command and what the tests assert
7. **Common errors** — the failure modes, and what each one *means*
8. **Commit message** — the change as it would be described in a commit
9. **SRS / report notes** — including the honest limitations
